# Setup and deployment

## Requirements

- Bun 1.2 or newer (Node 20 or newer also works with `npm`)
- A Supabase project (free tier is enough)
- A Vercel account for hosting, or any host that Nitro supports

## 1. Install

```sh
git clone https://github.com/yosrend/padelion-website.git
cd padelion-website
bun install
cp .env.example .env
```

## 2. Environment

| Variable | Where it is used | Notes |
|---|---|---|
| `VITE_SUPABASE_URL` | Browser | Supabase project URL |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Browser | Publishable (anon) key, safe to expose |
| `VITE_SUPABASE_PROJECT_ID` | Browser | Project ref |
| `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_PROJECT_ID` | Server rendering | Same values as above |
| `SUPABASE_SERVICE_ROLE_KEY` | Server only | Creates the demo staff accounts. Never expose it to the browser or commit it |
| `VITE_SITE_URL` | Browser and server | Public address of the site, no trailing slash. QR codes and the share image point here |

`.env` is ignored by git.

## 3. Database

With the Supabase CLI:

```sh
supabase link --project-ref <your-project-ref>
supabase db push
```

Or paste each file in `supabase/migrations` into the SQL editor, in file name order.

The last migration schedules the pg_cron jobs. On a new project, enable the `pg_cron` extension first (Database > Extensions) if the migration reports it missing.

Then enable Realtime on `bookings`, `payments`, `waitlist_entries` and `court_blocks` (Database > Replication) so the desk updates live.

## 4. Run locally

```sh
bun run dev
```

Open http://localhost:8080. Sign in to the staff side at `/staff/login`. The first sign-in creates the demo accounts listed in the README.

Other scripts:

```sh
bun run build      # production build
bun run preview    # serve the build
bun run lint
bun run typecheck
bun run test       # unit tests in tests/
```

`src/routeTree.gen.ts` is generated by the TanStack Router plugin when the dev server or a build runs.

## 5. Deploy to Vercel

The build uses the Nitro plugin (`nitro()` in `vite.config.ts`). On Vercel it writes the Vercel output format on its own, so no preset and no `vercel.json` are needed.

1. Import the GitHub repository in Vercel. Leave the framework preset on automatic detection.
2. Add the environment variables below in Settings, Environment Variables, for Production and Preview.
3. Deploy. Every push to `main` deploys again.

| Variable | Needed at |
|---|---|
| `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_SUPABASE_PROJECT_ID`, `VITE_SITE_URL` | Build time. Change one and redeploy, because the values are compiled into the browser bundle |
| `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_PROJECT_ID` | Runtime, server rendering |
| `SUPABASE_SERVICE_ROLE_KEY` | Runtime, server only. Never expose it to the browser |

Set `VITE_SITE_URL` to the final public address (the Vercel domain or your own domain), without a trailing slash. QR codes and the share image use it.

To check the Vercel output locally, run `VERCEL=1 bun run build`. The result is written to `.vercel/output`.

For another host, pass a different `preset` to `nitro()` in `vite.config.ts`. See the Nitro deployment docs for the list.

## 6. Going from demo to a real venue

1. Change the demo staff accounts and passwords, or remove `ensureDemoStaff` from the sign-in page.
2. Set the `is_demo` column defaults to `false` and unschedule `padelion-demo-reset`.
3. Replace the sandbox payment in `pay_booking` and `pay_balance` with a provider webhook (Midtrans or Xendit).
4. Add a worker that sends rows from `notifications` through the WhatsApp Business API and sets `sent_at`.
5. Set the venue name, address, WhatsApp number and photos.
